# 通知区域 Skill 自用记录

这不是预先编写三个采集例子的重复展示，也不是独立模型/弱模型对照实验。作者按冻结Skill1.0在固定Codex-Monitor图上实际探索一个有限的新区域，然后评估初稿、修订Skill和提案。

## 阅读顺序

1. proposal-v1.json 与 review-v1.md：初稿校验成功，但作者发现点击行为混淆、关键异常条件位置不当、引文覆盖不足和停止页未读。
2. Skill1.0冻结提交2bc979ce893cad2c30104aabc7040b3792774645，与当前skills/repographia-function-map/SKILL.md的1.1对照。
3. commands.json：实际25条CLI命令的顺序、参数与原stdout哈希。19-22是修订后的补查；23/24为重新check和submit。
4. proposal-v2.json 与 review-v2.md：2个功能、7条新映射、13条原始引文，仍为提案，不代替用户审阅。

完整交付包的trial/queries和commands.jsonl包含当时原始输出；仓库这里只保存归一化命令清单、哈希和提案/自评。stdout摘要可验证文件未被替换，但不能证明模型在认知上读过或理解过每一个字节。

## 复现边界

样本为490d822a9593d8d4b78a9188dd0daa0ae791eaf6。每份graph有自己的snapshot和元数据，不能把这些冻结提案直接塞到任意新图而只改hash。正常使用应按Skill重新探索，并用该图overview的header创建新提案。

scripts/verify-agent.mjs是固定源码与输入前提下的确定性CI复播；它会显式构造测试头部并核查已知源码哈希。它不启动模型、不再次做语义归纳，也不代表宿主会自动触发Skill。

## 满意与未满意的部分

修订后的功能边界和条件可用于一次初审；重要行为均有源码检查，不把外部通知、已读持久化或焦点成功变成保证。仍不满意的是匿名回调标签需要额外读理由才能理解，以及缺少陌生仓库/其他Agent的独立试用。后续应据实际失败修订，而不是只增加提示词长度或测试计数。
