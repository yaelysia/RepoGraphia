# Archify 右向树布局的有限复用

本记录对应 M4 的纯布局切片及 M4.1 同内容几何比较。复用对象固定为 Archify 提交 `25cf37080fc8b1dbe758a4efc3935b55f3327083` 的 [`archify/renderers/tree/render-tree.mjs`](https://github.com/tt-a1i/archify/blob/25cf37080fc8b1dbe758a4efc3935b55f3327083/archify/renderers/tree/render-tree.mjs)。已完成几何适配、10 项直接检查，以及固定中文阅读夹具的实际 DOM 测量；本轮接入选择可见投影，具体浏览器流程、阅读反馈和两平台完整回归仍以对应检查点为准。

## 采用的部分与保留的边界

`src/feature-tree.ts` 的 `createFeatureTreeApi()` 适配原 renderer 中 `// ---- Layout` 到 `edges` 构造完成之间的右向几何：同深度列宽、子树跨度、父节点按首尾子节点居中、接近中间子节点时的对齐，以及代际间隔中点的折线。完整固定源文件保存在 `third-party/archify/render-tree.upstream.mjs`，用于直接对照，生产浏览器不加载它。

这次没有搬入上游 CLI、SVG renderer、向下树的叶子堆叠、页面状态、浮窗、搜索、来源标记或文字测量依赖。调用方在实际字体和卡片样式下测量 DOM，再把宽高交给布局模块。布局不改名称、说明、父子关系或任何审阅内容，也不读取 FeatureMap、CodeGraph、快照、证据和人工决定。

完整 MIT 许可及 `2026 tt-a1i (Archify)`、`2025 Cocoon AI` 两条版权声明同时保留在 `third-party/archify/LICENSE` 和 factory 内部注释中。后者随 `createFeatureTreeApi.toString()` 进入离线 HTML，避免仅在源码仓库保留声明而遗漏实际分发的派生代码。固定来源、字节数和 SHA 见 `third-party/archify/README.md`；原 renderer 的 Git blob SHA 与 GitHub 返回值一致。`.gitattributes` 将两个固定源文件锁为 LF；摘要始终检查原始字节。嵌入注释的比较单独统一 LF/CRLF，与 `renderHtml` 在生成 CSP 哈希前的规范化一致。

## 输入与输出契约

```ts
const tree = createFeatureTreeApi();
const result = tree.layout(nodes, { gapX: 64, gapY: 24, padding: 24 });

// nodes:
// readonly { id: string; parentId?: string; width: number; height: number }[]

// result:
// {
//   nodes: { id: string; x: number; y: number; width: number; height: number }[];
//   edges: { parentId: string; childId: string; points: [number, number][] }[];
//   width: number;
//   height: number;
// }
```

| 项目 | 契约 |
| --- | --- |
| 坐标 | CSS 像素，向右增加深度，纵向排列同级与根；保留小数精度。 |
| 节点 ID | 任意非空原字符串，以 `Map` 存储；不替换、不散列、不转为 CSS selector。DOM 如何引用仍由调用方负责。 |
| 父子关系 | 只使用输入中明确的 `parentId`；允许多个根，不创建虚构功能根。所有被引用的父节点必须在同一输入内。 |
| 顺序 | 根和同级顺序遵循输入顺序；输出节点维持输入顺序，输出边维持其子节点的输入顺序。输入无需先父后子。 |
| 宽高 | 输入宽高必须是有限正数。每一深度的输出宽度统一到该列最大测量宽度，绝不缩小；高度保持输入值。调用方按输出宽高放置卡片。 |
| 间距 | `gapX = 64`、`gapY = 24`、`padding = 24`；允许有限非负数。`padding` 包含左右上下留白。 |
| 连线 | 返回原父子 ID 和折线坐标，不带调用方向、执行顺序、证据等级或功能依赖声明。 |
| 边界 | `width`、`height` 包含所有输出节点及 padding；没有上游 SVG 的最小画布、标题区或展开圆按钮余量。 |
| 空输入 | `{ nodes: [], edges: [], width: 0, height: 0 }`。 |
| 非法输入 | 重复 ID、缺失父节点、环、无效宽高/选项、超出有限坐标范围时抛出以 `Feature tree:` 开头的错误；不悄悄修补语义。 |
| 状态 | 不修改输入、不持有跨调用状态、不发请求；不包含展开、相机、选中或人工审阅状态。 |

模块使用迭代遍历，没有自设深度上限。文档接收层已有的数量与预算限制仍然生效；布局测试中的 10,000 层合成链只是验证几何计算不依赖递归，不表示产品可接收同样大小的功能文档。

## 完整树与可见投影的接缝

布局模块只处理调用方给出的有效 forest，不替产品决定展开策略。两种接入均可使用同一个 API：

1. **传入完整树，再筛选可见节点和边。** 全量卡片尺寸保持一致时，折叠不改变坐标；宽或不平衡子树可能留下很大空白。
2. **传入当前可见节点及其全部祖先。** 布局只为可见内容预留空间；展开后会重新计算列宽、子树跨度和坐标。调用方负责用点击节点作为相机锚点，并对旧节点施加有限位移动效，避免阅读位置突然丢失。

两种方式都必须保留原 ID 和真实父子关系，不能为了适配布局删改文档中的关系。不要把可见子节点单独传入而漏掉其父节点。跨版本恢复状态、返回原功能、聚焦模式兼容和 `prefers-reduced-motion` 属于 viewer 的验收项。

## M4.1 同内容测量与接入选择

比较使用 `tests/helpers/feature-tree-reading.mjs` 明确编写的阅读夹具，冻结为 `reports/m4-reading-input/graph.json` 与 `features.json`。共有 39 个功能、2 个真实根，包含 13 层路径、20 个同级和不平衡分支；这不是从用户项目推测出的功能架构，也不是实际用户验收数据。比较时的代码快照为 `805c9d47689b2d1539ed6263923e8edde0489c889d1bf2a88a761c75435bec91`，`features.json` 字节 SHA-256 为 `914ef5ebabf6b88eb78dcc4797c435fc3f933979f233db1ba153fd86f00eaa1f`。

2026-10-23 在 Linux Chromium 中实际打开冻结的 `file://` 报告，以 1440 × 1000 视口展开全部卡片，读取中文 DOM 的 `offsetWidth` / `offsetHeight`：功能卡宽 260 px，通常高 161 px，`final`、`deep-12` 两张长名称卡高 186 px；范围卡为 224 × 122 px。该次报告的 SHA-256 为 `d0258f5c29c141ddae7dde6591e3674314c7cf299b67aeea83ad36ba73d60f8a`，用于固定测量所对应的样式版本；后续 CSS 调整不能追溯性地算进这些数字。

随后把同一组实际测量尺寸交给同一个 `FeatureTree.layout`，使用 `gapX = 64`、`gapY = 28`、`padding = 24`，只改变传入的可见投影。比较没有使用缩小字号或缩放整图来压缩空间。“可见内容高度”是显示节点（含范围卡）的外接范围；“同列最大空白”是同列相邻可见节点边界之间的最大纵向距离。完整树布局的画布在三种状态下均为 4484 × 4581 px。

| 阅读状态 | 可见功能 | 全树布局后隐藏：可见内容高度 | 全树布局后隐藏：同列最大空白 | 可见投影：画布 | 可见投影：可见内容高度 | 可见投影：同列最大空白 |
| --- | ---: | ---: | ---: | --- | ---: | ---: |
| 全部收起，只显示两个根 | 2 | 1600.375 px | 1278.375 px | 596 × 398 px | 350 px | 28 px |
| 仅展开 `window` | 5 | 2737.5 px | 1823.5 px | 920 × 776 px | 728 px | 217 px |
| 展开 `window`、`open`、`prepare` | 8 | 2737.5 px | 1823.5 px | 1568 × 965 px | 917 px | 358.75 px |

因此本轮 viewer **采用可见投影**：在正常文字尺寸下，隐藏的深宽分支不再持续占用全部跨度；展开引起的重排通过点击节点的相机锚点补偿和有限位移动效呈现。原地收起保留选中功能及说明，定位隐藏选择和搜索时再打开必要祖先；聚焦、搜索与源码往返使用独立阅读快照恢复相机、展开、分页和阅读区状态。这些是接入策略及待浏览器流程验证的行为，几何数字不替代交互验收。

本次比较只读取冻结 JSON 和页面尺寸，构造 `{id, parentId, width, height}` 几何输入；不调用标注编辑或 Agent，不更改任何名称、说明、问题、映射、依据、人工决定或历史。范围卡的合成 ID 仅存在于 viewer 的几何输入，不写入功能文档。浏览前后导出 JSON 的完整不变性仍由 `check-feature-tree-reading.py` 检查，不将本次数值对照扩展为“全部语义没有错误”的结论。

## 对原算法的明确调整

| 调整 | 原因及验证 |
| --- | --- |
| 单根扩为 forest，共享深度列，根之间按子树跨度分隔 | RepoGraphia 允许多个真实根；不添加会进入功能语义的虚拟根。任意 ID、子节点先于父节点、多根顺序均有直接检查。 |
| 递归换为迭代遍历 | 避免功能深度触发 JavaScript 调用栈上限；512 个同级与 10,000 层链的合成检查通过。 |
| 父节点中心限制在其已预留子树跨度内 | 原算法在父卡特别高、子节点高度不均时，会把父卡移出本子树跨度，与同列下个兄弟重叠。回归用固定原代码实际复现该重叠，再检查适配后的节点互不重叠。 |
| 保留小数坐标，不强制四舍五入 | DOM 测量可以含小数；在零间距条件下，像素取整会把节点推入相邻区域。小数尺寸、零间距和画布边界有检查。 |
| 近齐平连线使用两中心的平均纵坐标，并确认仍落在两个节点高度范围内 | 保留上游减少细小折线的思路，同时兼容小数尺寸；其余连线仍经过列间距的中点。 |
| 不采用文字估宽和 SVG viewBox 下限 | 文字排版由实际 DOM 测量，画布边界由卡片和 padding 决定；这不是完整原 renderer 的等价替换。 |

## 实际对照和已验证范围

`tests/feature-tree.test.mjs` 校验原 renderer 的 SHA-256 和 Git blob SHA，再从固定文件取出原始纯几何块，为其提供测量结果、父子索引和右向配置。测试没有导入原 CLI 模块，没有执行加载器、安装依赖或启动被分析项目。三份正常测量输入覆盖多同级、不平衡深浅分支、同列不同宽度以及高卡片；在没有触发上述修正的情况下，节点坐标、尺寸和每条连线坐标与原实现逐值一致。存在预期差异的高卡重叠场景单独作为回归检查，未被算入“完全一致”。

本切片在 Node.js 24.19.0 的 Linux 环境用 TypeScript 严格模式独立编译，并通过 10 项检查：固定来源与完整嵌入许可、真实上游几何对照、forest/原 ID/顺序、高卡重叠、长尺寸与宽度带、宽深合成树、小数尺寸、输入不可变与语义隔离、独立浏览器式 realm 执行、空输入和非法结构。完整工程集成及 Windows、真实离线浏览器检查不由这组纯几何结果替代。

当前复用成立的依据是：原算法确实负责主要布局公式，固定来源可追溯，正常输入可直接比较，RepoGraphia 特有的 forest、尺寸和离线嵌入边界有独立覆盖；同一冻结内容的空间比较支持本轮采用可见投影。若实际页面中宽深分支的空白、定位或文字截断仍使阅读失败，就继续调整视图接入；几何对照通过不等于阅读验收已经通过。
