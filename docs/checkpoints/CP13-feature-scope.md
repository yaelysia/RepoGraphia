# CP13 — 功能与代码映射层开工

2026-10-20，基线 CP12 `a64c67bb7e111a2a8c2e2f1f7a30677e2a1051ea`，工作分支 `feat/feature-code-mapping-r1`。PR #3 尚未合并，本阶段作为其后的独立变更，不向 Codex-Monitor 写入代码。先读 AGENTS.md、docs/architecture.md 和 docs/CHECKPOINT.md，再看后续提交。

## 本轮验收范围

1. 独立 JSON sidecar：功能、显式多对多代码关联、角色、理由、声明及关系证据。不得从共同依赖自动推导功能之间的业务关系。
2. 映射评审与代码有效性分离：proposed/accepted/rejected 只是作者申报的审阅状态，不是程序证明。AI 示例必须标作 agent 提案，不冒充用户确认。
3. 严格绑定分析快照、规则版本、编译配置、源码哈希与实体区间。变化后明确失效，不以同名或新偏移自动重新匹配，也不执行增量迁移。
4. 浏览器/CLI 共用验证和修正逻辑。人工修改有显式作者、版本冲突检查、修改记录和 JSON 导出；页面修改只是内存草稿，不假装已经保存到仓库。
5. 用少量固定 Codex-Monitor 功能提案打通功能 → 代码 → 原关系/来源证据与反向导航。保留未知区域，程序校验锚点不等于证明业务语义。
6. 正反例覆盖多对多、不确定性保留、拒绝映射、过期/缺失证据、同名替换、编辑冲突、导入错误、HTML 注入；既有静态图在同输入下不得改变。
