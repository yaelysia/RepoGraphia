# CP43 — 工作区离线导出的引用核对一致性

2026-10-23（Asia/Shanghai），分支 `fix/offline-reference-export`，基线为远端 master `fac543b52dd46a68e624387f70ebd19acdd43c29`，tree `dcaa6b1c6e24a8955931e506d55905c559cb2fcd`。接手时远端没有未合并 PR。

## 问题与定位

用户报告在固定 Codex-Monitor `490d822` 的独立源码副本上完成 M1→M2→M3：8 个浏览器阶段、45 次 Agent CLI 调用、3 个功能与 10 条待审映射。其工作区显示 10 条依据匹配，离线 HTML 却全部失效。本轮没有取得或重跑该用户产物；这些数量是用户试用反馈。

`/api/export` 原先只把 graph 与 features 传给 `renderHtml`，未携带工作区根据原始版本计算的 `FeatureReferenceReport`。旧标注仍严格绑定其原快照，所以离线 `assess` 会把跨快照记录判为 stale；工作区同时拥有另行计算的逐条引用核对，因此出现展示差异。

已用真实分析的小型夹具复现：无关文件新增调用导致全局关系 ID 改变，原引用的精确源码与静态邻域仍匹配；旧导出缺少 `feature-reference-data`。该结果不能被解释为用户功能说明、异步行为或外部行为已经验收。

## 修复与边界

- 工作区通过可复用的引用读取入口，对明确指定的代码快照与标注 digest 计算核对，不为导出加载无关任务／提案记录。
- 渲染器在嵌入结果前核对协议版本、代码快照、标注摘要与修订号、映射及功能成员、原决定／依据和精确当前目标。非匹配项不能携带当前跳转目标。
- 独立 HTML 使用惰性 JSON 携带派生核对，标明“导出版本引用核对”。无工作区桥接、凭据或联网能力；关闭服务后仍可读。
- 摘要、功能卡片（含分页）、代码节点和详情采用相同引用状态；匹配项用核对后的节点／关系 ID 导航，保留候选、外部边界、来源不完整等限制。
- `MappingAssessment.current` 与原标注不被修改。接受旧依据的限制、显式迁移和原始调用箭头仍使用严格规则，不因展示匹配自动迁移或接受。
- 成功编辑、导入或迁移标注后撤销冻结核对；失败导入保留原标注与核对，防止相同映射 ID 套用另一份文档的结果。

未修改 CodeGraph、FeatureMap、Agent 协议、Skill 或分析规则；未修改目标项目，也未重跑用户的 Agent。

## 接手与复测
