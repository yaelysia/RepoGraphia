# CP28 — 极简功能工作台落地计划（2026-10-22）

## 基线与用户选择

远端 `master` 已核对为 `d277ab5d6cdf03e40f7d6fdfafc810ae51e5c939`，PR #8 的合入结果与 CP27 一致。工作分支：`feat/minimal-function-workbench`。用户比较了可交互方案后选择第一版「极简工具」，并明确要求开始正式落地。

视觉基准：胶囊名称、下方一句解释、左侧节点图与右侧说明；进入/返回有明显的横向位移和缩放，选中与展开有短过渡。复杂功能按实际标注深度浏览，不能限制成只进入一次。

## 实现边界

- 复用当前离线 HTML、共享 FeatureMap API、关联代码投影、源码/证据与人工审阅；不引入前端框架、远程字体、外部脚本或新模型调用。
- 当前标注只有扁平功能。FeatureMap schema 3 增加可选 `summary` 与 `parentId`，仅表达作者明确提供的摘要和包含关系。旧 schema 1/2 的纯浏览保持原样；首次写入新字段才升级，并保留每条映射的原快照。
- 严格校验父功能存在、无自指、无环；迭代遍历，沿用文档数量预算，不设置功能深度上限。Agent、迁移、导入导出与编辑器使用同一契约。
- 旧功能没有父子定义时仍显示为顶层；没有摘要时只展示原说明的视觉截断预览。不得自动拆分功能、改写原描述、把代码角色当步骤或从共享代码推断功能依赖。
- 层级连线表示包含。原始代码调用继续显式开启且保留候选状态。概念原型中的行为流程不冒充实际仓库分析结果。
- 保存每层视图、选中、展开范围和镜头，源码/证据返回恢复浏览上下文。窄屏右侧详情抽屉不改变层级语义。

## 验证与阶段交付

1. 共享数据契约单测：旧文档不变、schema 3 编辑/迁移/Agent、深层导航数据、非法父节点和环、输入不变。
2. 浏览器：旧功能/审阅/迁移/Agent 语义回归；新层级、镜头、源码往返、快速切换、减少动效、长文本和左右布局；保持原 CSP 文件启动正反例。
3. 锁定依赖 `npm test`、新旧 viewer 语法检查、Windows/Linux CI 与固定样本任务。仅报告实际运行结果。

本计划记录范围与恢复入口，不是完成声明。实现与验收完成后分别更新新的检查点；历史检查点保持不改。
