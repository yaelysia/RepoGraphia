# 功能地图：展开功能树与阅读代码依据

本文说明 M4 的功能树阅读实现；设计范围见 [M4 方案](function-tree-reading-plan.md)，固定 Archify 几何复用与同数据比较见 [复用记录](archify-tree-reuse.md)。实际交付版本与跨平台验收以检查点和对应 PR 为准。

功能地图与项目代码地图共用固定暗色工作台：墨蓝底、蓝紫强调色、渐变光晕与细点阵。系统使用浅色偏好时也保持暗色。默认阅读路径是 **选择功能 → 阅读解释 → 原地展开或聚焦一支 → 查看代码依据与审阅**。左侧画布保留已展开的父子功能与同级上下文，右侧阅读区承载长文和操作；620 px 及以下使用可关闭的右侧阅读抽屉，736 px 仍保持左右布局。界面不增加模型调用，也不改写分析结果、功能含义或审阅决定。

顶部「项目地图 / 功能映射」、搜索框与工作区外框保持同一位置，模式切换只改变内容。导航树在两种模式中都按需打开；「项目概况」展开快照指标，「说明与依据」控制右侧阅读区。切回项目地图时恢复原目录、筛选、选中项和阅读位置，源码与证据也使用同一套界面。

## 选择、展开与聚焦各做一件事

功能卡片显示名称和一句解释，下面保留关联数量及依据状态；底部的展开按钮直接标明子功能数量。标题最多显示三行，解释最多两行；完整名称和原说明可在右侧阅读。解释优先使用标注中的 `summary`，没有时截取原 `description`，不会自动生成或改写摘要。

- **点选节点**：在右侧查看该功能，不改变阅读范围，也不自动跳入代码。
- **展开 / 收起**：在当前图中显示或收起这条分支，保留父节点和同级上下文。子节点可以继续展开，深度由标注中的实际结构决定。
- **聚焦**：把这一支作为独立阅读范围。顶部「返回阅读位置」回到进入前的范围、展开、选择、缩放、画布与右侧阅读位置；路径栏仍可直达上级或全部功能。
- **查看实现 / 关联代码**：进入该功能显式关联的代码。没有子功能的节点会提供「查看实现」入口；已有子功能也可以单独查看自己的代码关联。

「全部功能 / 聚焦范围」卡只是导航范围，不会成为有证据或审阅决定的新功能。没有子功能仅表示尚无分解标注，不代表已经分析完成。

功能之间的细线只表示标注中明确写出的 `parentId` 包含关系，不表示调用、依赖或执行顺序。父功能的代码映射不会自动分给子功能，共享代码也不会产生新的父子关系。

schema 1/2 的旧标注没有层级字段，因此仍作为顶层功能显示；它们不会因换了界面而凭空获得子功能。浏览和重新渲染不会修改标注。首次保存 `summary` 或 `parentId` 时才升级到 schema 3，并保留原映射的证据快照。已有层级的深度受文档总量预算约束，界面不另设固定深度上限。

## 定位与返回

画布初次打开使用 **100% 缩放**，优先保留可读字级。拖动空白处移动画布，使用加减按钮或 Ctrl + 滚轮缩放；「适应」根据当前画布和已显示节点调整缩放与位置。同级节点较多时按需显示更多，缩小总览后可放大阅读单个节点。

顶部全局搜索可按功能名称、解释、说明或 ID 定位。结果在当前阅读范围内时，自动揭示必要祖先和分页，不切换到结果的直接父级；结果在范围外时返回全部功能并揭示对应分支。搜索也会保留搜索前的阅读快照，可用返回按钮恢复。收起包含当前选择的分支时，右侧仍保留该功能，工具栏提供「定位已收起的选择」重新展开并定位。

每条分支先显示 12 个直接子功能，更多按钮明确显示已显示数和总数；内容没有被删减。布局只为已显示节点预留空间，避免隐藏子树造成大片空白。展开重排以点击位置为锚点，并将新出现的首个子节点平移到视区；不会自动缩小整棵树。功能树按需打开，长路径可以横向滚动。

关联代码的图/列表模式、各组展开范围、分页、原始调用开关和滚动位置仍按功能分别保留。查看源码或证据后，可通过「返回功能映射」回到原来的功能、画布位置与展开范围。这些画布与说明区状态在当前会话中保存；工作区可重开不等于画布视角跨会话持久化。

主模式和目录切换使用约 **460 ms** 的横移与缩放；功能层级从约 **56 px** 偏移和约 **8%** 的缩放差进入。树分支展开、收起与位置变化约 **360 ms**，相机平移约 **380 ms**。键盘可用 Enter / Space 激活按钮，用左右方向键展开、收起或定位父子节点。代码组展开约 **330 ms**、收起约 **280 ms**，通过局部裁切和淡入淡出体现范围变化。快速往返会取消前一动画，背景和连线没有循环流动效果。系统启用 `prefers-reduced-motion` 时直接完成状态切换。动效表示进入、返回和展开，不模拟代码运行。

## 右侧分开阅读说明、依据和审阅

| 页签 | 阅读内容 |
| --- | --- |
| 说明 | 一句解释、默认折叠的完整功能描述、待确认问题；选中代码时显示原关联理由和源码入口 |
| 依据 | 显式关联数量、证据限制、原符号与位置、哈希及原始关系，按需展开 |
| 审阅 | 编辑功能、修改映射决定和查看历史；人工接受仍需要编辑者与理由 |

证据失效始终显式显示，不能按同名函数自动重绑。人工接受只记录审阅决定，不会把候选调用升级为确定调用。离线页面中的修改仍只在内存里，必须在「标注与文件」中导出 JSON 才能保存；本机工作区沿用明确的保存确认与冲突处理。

## 构造与提案阅读

本机工作区仍从「继续分析这个功能」准备固定范围的外部 Agent 任务。展开只显示已有标注；准备任务和应用提案是独立操作。Skill 1.4 增补本层问题、同层粒度与分解理由，详见 [功能建设](feature-tasks.md)。

功能建设中的提案先按功能选择，再阅读本功能的内容与关联变化、支持与限制。完整前后内容、原变更索引和每条检查保留，检查只属于该固定提案及其代码版本。仅撤销和仅探索不会被补成虚构功能；旧批次沿用任务基线中的功能名称。整批应用、逐映射决定和开发审阅仍是各自原有的记录。

## 关联代码仍沿用原证据规则

代码画布左侧保留当前功能，右侧按既有 `entry / implementation / support / test` 角色排列。默认展示前三个入口和前四个实现；支撑与测试默认折叠，但总数和展开操作始终可见。排序沿用标注顺序，不把排序解释成重要性或执行顺序。每组最多展开 50 条，更多内容通过「全部关联」每次增加 25 条访问。角色列在画布内部横向滚动，不把右侧阅读区推到页面下方。

代码节点显示原标签与关联理由摘录，完整理由留在右侧。方法标签补充真实词法父级，如 `Controller.show`；匿名回调显示可用的所属上下文和文件/行号。原名称和准确 ID 在定位信息中保留。失效锚点不读取当前同 ID 实体来补标签，更不会按同名重绑。

默认细线表示 **功能与角色组中的代码有显式映射**。已拒绝、失效项保留标记供追溯，不能充当当前有效调用的端点。「叠加原始调用箭头」只使用当前图中已有的 `call / construct / tag` 记录，且两端必须是已展开、证据匹配、未拒绝的映射实体。候选箭头为虚线；回调传入、JSX、导入、继承不会变成调用。

同一实体对按关系种类/状态聚合，原始关系 ID 全部保留，可在「原始调用记录」中逐项进入原证据。每次最多画 32 对，折叠端点、功能外/未知目标、自调用和预算省略均独立披露；这些计数可重叠。共享实体只显示另有几个功能显式关联它，不推断功能依赖。代码画布宽度小于 620 px 时不画原始调用箭头，完整调用记录仍可展开。图和列表都是已有标注的投影，不构成完整的运行时调用图。

## 已有提案无需重新让 Agent 生成

更新工具后，使用 **该提案原来对应的 graph.json** 和原 features.json 构建并重新渲染：

```sh
npm run build
node dist/cli.js features render "./reports/codex-monitor-r1/graph.json" "./reports/agent-trial-result-01/features.json" --out "./reports/feature-workbench.html"
```

输出文件必须不存在；已存在就换新名字。打开新 HTML，点击「功能映射」。旧报告不会随工具更新自动变化。原图与标注必须配对，不需要重新扫描或重跑 Agent；不同快照应走既有显式迁移流程。

切换节点、展开代码、拖动画布和查看源码都不会修改图或功能标注。导出 JSON 才会保存人工编辑，HTML 文件本身不会被页面更新。

## 验证

`src/feature-scene.ts` 是供浏览器复用的只读展示投影。`tests/feature-scene.test.mjs` 覆盖角色预算、词法标签、共享代码、候选与多目标、失效/拒绝隔离、关系去重及输入不变。层级契约由 `tests/feature-hierarchy.test.mjs` 检查。新几何模块 `src/feature-tree.ts` 的固定来源、直接上游对照、多根和实际深度由 `tests/feature-tree.test.mjs` 检查。

`tests/helpers/feature-workbench.mjs` 提供独立手写的多层功能、较多同级节点、空映射、非法循环导入和 HTML 形状摘要等夹具。`scripts/check-feature-workbench.py` 检查选择与进入、逐层返回、搜索定位、画布和代码状态恢复、快速往返、减少动态效果、窄屏布局及导入导出；夹具不表示真实程序的执行路径。

新增 `tests/helpers/feature-tree-reading.mjs` 提供固定的 39 功能、13 层深度、20 同级与不平衡树；`scripts/check-feature-tree-reading.py` 使用真实点击、键盘和画布拖移检查展开、聚焦、搜索、返回、分页、中文阅读尺寸、右侧状态与导出不变。工作区隐藏 iframe 时延迟测量，重新显示后再测量和定位。

浏览器检查需要 Python Playwright 和 Chromium。首次准备检查环境：

```sh
python -m pip install playwright==1.55.0
python -m playwright install --with-deps chromium
```

构建、生成新的夹具目录并检查：

```sh
npm test
node tests/helpers/feature-scene.mjs reports/feature-scene
python scripts/check-feature-scene.py reports/feature-scene
node tests/helpers/feature-workbench.mjs reports/feature-workbench
python scripts/check-feature-workbench.py reports/feature-workbench
python scripts/check-workbench-shell.py reports/feature-workbench
node tests/helpers/feature-tree-reading.mjs reports/feature-tree-reading
python scripts/check-feature-tree-reading.py reports/feature-tree-reading
```

`check-workbench-shell.py` 另检查系统浅/深偏好下的固定暗色、模式切换外框连续、项目状态恢复、有限动效、窄屏抽屉及浏览前后的标注不变。夹具输出目录必须尚不存在。检查默认在 Chromium 中真实打开 `file://` 报告，Windows/Linux 的验证流程同时保留原有离线页面、功能编辑、迁移、Agent 报告及 CRLF/CSP 回归。当前完成状态以检查点和对应 CI 记录为准，不由命令示例或截图数量证明。浏览器夹具不包含用户上传的代码或试跑包，也不构成语义正确率或独立用户可用性评测。
