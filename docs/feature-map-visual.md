# 功能地图：从概览到源码证据

功能地图以人为主要读者。默认阅读路径是 **功能节点 → 角色分组的关联代码 → 说明和证据**，不是把所有审计文字同时铺在画布上。它不增加模型调用，也不更改分析结果、功能含义或审阅决定。

## 三层阅读

1. **概览节点**只展示原功能标题、关联/文件/问题数量及审阅状态。长标题最多显示三行，悬停或选中查看完整内容。不会自动缩写、改写或把目录重新命名为功能；功能之间不生成依赖箭头。
2. **关联图**按既有 `entry / implementation / support / test` 角色分组。默认展示前三个入口和前四个实现；支撑与测试默认折叠，但总数和展开操作始终可见。排序沿用标注顺序，不把排序伪装成重要性或执行顺序。每组最多展开 50 条，更多内容通过「全部关联」每次增加 25 条访问。
3. **右侧审阅**展示完整功能说明或所选代码的关联理由。待确认问题、证据限制、原始符号/位置/哈希、原关系、修改决定和历史分层展开。证据失效始终显式显示；接受仍需要编辑者与理由，且不会把候选调用变成确定调用。

方法标签补充真实词法父级，如 `Controller.show`；匿名回调显示可用的所属上下文和文件/行号。原名称和准确 ID 在定位信息中保留。失效锚点不读取当前同 ID 实体来补标签，更不会按同名重绑。

## 两种不同的连接

默认细线表示 **功能与角色组中的代码有显式映射**，不是调用或运行顺序。已拒绝、失效项保留标记供追溯，不能充当当前有效调用的端点。

「叠加原始调用箭头」只使用当前图中已有的 `call / construct / tag` 记录，且两端必须是已展开、证据匹配、未拒绝的映射实体。候选箭头为虚线；回调传入、JSX、导入、继承不会变成调用。

同一实体对按关系种类/状态聚合，原始关系 ID 全部保留，可在「原始调用记录」中逐项进入原证据。每次最多画 32 对，折叠端点、功能外/未知目标、自调用和预算省略均独立披露；这些计数可重叠。共享实体只显示另有几个功能显式关联它，不推断功能依赖。

窄屏时按角色纵向排列，不画交叉箭头；完整调用记录仍可展开。图和列表都是已有标注的投影，不构成完整的运行时调用图。

## 已有提案无需重新让 Agent 生成

更新并构建工具后，使用 **该提案原来对应的 graph.json** 和原 features.json 重新渲染：

```sh
node dist/cli.js features render "./reports/codex-monitor-r1/graph.json" "./reports/agent-trial-result-01/features.json" --out "./reports/feature-map-v2.html"
```

输出文件必须不存在；已存在就换新名字。打开新 HTML，点击「功能映射」。旧报告不会随工具更新自动变化。不要为使用新界面重新扫描再修改 snapshot；不同快照应走既有显式迁移流程。

页面上的编辑仍只在内存中，导出 JSON 后才能保存。切换节点、展开支撑或查看源码都不会修改图或功能标注。源码返回会保留原功能、图/列表模式及展开范围。

## 验证

`src/feature-scene.ts` 是供浏览器复用的只读展示投影。`tests/feature-scene.test.mjs` 覆盖角色预算、词法标签、共享代码、候选与多目标、失效/拒绝隔离、关系去重及输入不变。

```sh
npm test
node tests/helpers/feature-scene.mjs reports/feature-scene
python scripts/check-feature-scene.py reports/feature-scene
```

浏览器检查使用独立手写夹具，不把用户的代码或试跑包提交到仓库。CI 在 Windows/Linux 均真实打开 file://，并保留原有离线页面、功能编辑、迁移、Agent 报告及 CRLF/CSP 回归。图片上的关系数量不是语义正确率，也不代表独立用户可用性评测。
