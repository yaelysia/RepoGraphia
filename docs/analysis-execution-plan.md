# 下一阶段提案：工作台内的功能分析（M4）

2026-10-23。**准备阶段的建议范围，尚未实现。** 用户已反馈前面功能测试正常，要求预备下一阶段。本文件承接 [产品方向](product-direction.md) 中“初版外部 Agent、后续界面启动与运行管理”的顺序；具体交付以之后的实现检查点和实际验收为准。

## 1. 这阶段要改善什么

让用户从功能图出发，提出一个有范围的问题，在同一个工作台看到分析状态、读懂返回的提案，再决定是否加入功能图。项目粗图、逐层深入和按变化续分析继续使用同一套任务；功能深度由实际内容决定。

现有人工交接已经可用：准备任务、下载任务包、交给外部 Agent、导入结果、审阅应用。M4 建议接通本机 Agent 的启动与收件，减少手动搬文件。成功标准同时包含**操作顺畅**和**人能理解本批结果**。进程退出、JSON 有效、引用匹配都不能单独表示理解正确或开发完成。

M1～M3 及导出修复已得到用户本轮测试通过的反馈；主分支 `0ef69d3dc9256dbfeea7a8bd625004a84c9525b5` 的 [Verify #63](https://github.com/yaelysia/RepoGraphia/actions/runs/39914395704) 为 `completed / success`。这是本次准备的实现基线。

## 2. 优先级与取舍

| 内容 | 建议安排 | 原因与验收边界 |
| --- | --- | --- |
| 从工作台发起功能分析、自动收回待审结果 | M4 主线 | 接续已经确定的操作路线，复用现有任务与人工审阅；减少交接步骤 |
| 按功能组织本批变化、理由、支持与限制、未确认事项 | 与 M4 一起验收 | 这些数据已有协议承载；运行结果应直接连到可读的审阅对象，不能只出现终端日志 |
| 多批次持续建设粗图、按实际深度深入 | 沿用 M2，纳入 M4 试用 | 每批仍是有界任务；未探索区域和实际索引范围持续可见，不能因自动执行就宣称全项目完成 |
| 自动解释一轮开发的行为变化、目标达成与影响 | M4 之后单独设计 | M3 当前保存事实比较和独立来源的解释。新的行为解释需要绑定前后证据与不确定性，不能从功能提案或文件交集直接推导 |
| 底层真正局部增量提取 | 先保留为测量驱动的专项 | 当前自动完整重建已可用；尚无本轮性能数据证明它是首要瓶颈，正确性仍需跨文件依赖与完整重建对照 |

用户这次确认的是前面功能测试正常。上述排序是开发建议，不是用户另行报告了内容质量、性能或手工交接故障。M4 也不承担自动写目标代码、自动判断运行行为或自动完成测试的承诺。

## 3. 用户实际会怎样使用

1. 在功能图选中一个功能，点击“继续分析”；也可以从“项目粗图”或“按变化续分析”进入。右侧先说明本次要弄清什么、依据哪个版本、涉及哪些范围。
2. 选择已配置的本机 Codex 并点击“开始分析”。保留下载任务包和手动导入入口，已有外部 Agent 用法继续可用。建立开发起点、打开地图、文件保存都不会触发模型。
3. 运行期间看到是否仍在运行、最近一次可核实活动、耗时以及取消入口。Agent 返回的活动说明明确标来源；精确命令与日志放在展开区。没有可用活动事件时只显示“运行中”，不编造步骤或百分比。
4. 结果经校验后进入原有待审提案区，提示“结果已就绪”。用户主动打开后，先看本批名称与一句说明，再看新增/修订/撤销、理由、支持与限制依据、未探索事项，最后作整批决定。
5. 应用之后可以回到对应功能节点继续下钻。新关联和含义改变的关联保持待审；功能关联决定、开发审阅结论与测试结果继续分别保存。

沿用暗色、左右工作台和现有地图导航。运行区域放在现有“功能建设”的任务详情，不另造一套聊天首页。动效用于开始、状态转换、结果到达和进入/返回；遵守减少动效设置，持续运行不靠不断闪烁表示进度。后台通知不会替换正在看的版本、打断表单或自动切换功能。

### 本批结果的阅读顺序

| 用户的问题 | 优先显示的已有内容 | 需要继续展开的内容 |
| --- | --- | --- |
| 这次提出了什么？ | 提案摘要、功能名称与一句解释、变化类型 | 完整前后文本和精确变更 |
| 为什么改成这样？ | 本项修订理由 | 关联代码、来源与候选限制 |
| 依据是什么？ | 对应功能的支持说明和限制说明 | 精确引文、位置、源码跳转 |
| 还有什么不确定？ | 本功能待确认问题、本批未探索事项入口 | 全部范围记录和系统核对边界 |

这些是现有提案信息的组织与导航。当前 `checks` 已带 `featureId`，可以把批次统一折叠的依据汇合到当前功能/关联变更旁；缺少内容时如实显示。仅撤销关联的提案继续按现有协议显示原因与原记录，不为凑齐卡片编造新检查。先展示原始记录，避免依靠额外模型生成“总结”而丢失条件。Skill 中完整 claim table 和自评目前主要保存于试跑文件，不属于已返回的提案字段；若要持久化逐句声明或对本轮代码行为作新解释，需另立协议，不把它们偷偷塞进当前 `revisionProtocol: 1`。

## 4. 复用现有契约

| 已有能力 | 当前实现 | M4 如何接入 |
| --- | --- | --- |
| 固定任务及允许修订范围 | `ContinuousWorkspace.prepareFeatureTask`、`featureTaskBundle`；`src/feature-tasks.ts` | 同一任务包交给执行适配器，保留 task/snapshot/digest/revision |
| Agent 查询、check、submit | `src/feature-task-cli.ts`、`src/feature-tasks.ts`；Skill 1.3 | 继续使用 `agent task` 路线及 receipt，不另造一份功能提案格式 |
| 收件、去重、结构与证据校验 | `ContinuousWorkspace.importFeatureProposal` | 运行器收件后调用同一入口；内容摘要去重、冲突仍明确报错 |
| 原子人工应用与迟到保护 | `featureProposal`、`decideFeatureProposal`、`checkedFeatureBaseline` | 自动收回只进入待审，应用仍重新核对当前代码、标注和本机输入 |
| 暗色任务与提案工作台 | `viewer/workspace-analysis.js` 的 `renderTask`、`renderProposal` | 增加运行状态与结果入口，复用原前后比较和决定表单 |
| 本机服务与可靠保存 | `src/workspace-server.ts`、`src/workspace.ts` | 继续使用本机 token、Host/Origin 检查、单写入者与原子发布 |

当前 `renderTask` 明确显示“执行状态未知”，只提供下载和导入。`renderProposal` 已经包含摘要、前后差异、理由、支持/限制与范围，不能把这些已有能力重复宣称成 M4 新实现。M4 新增的是运行尝试、真实状态、可靠收件以及它们与功能阅读流程的衔接。

## 5. 新增运行尝试，保留任务与提案各自身份

一个固定分析任务可以有多次运行尝试。每次尝试有独立 `runId`、任务包摘要、开始/结束时间、适配器和 CLI 版本、所用工具/Skill 版本、事件记录及结果文件位置。重试不覆盖前一次目录；相同提案重复收件由现有内容摘要幂等处理，不产生多份决定。新生成的不同提案遵守原有唯一 batch 规则。

运行记录与 M1 的开发起点任务、M2 的功能分析任务分别保存。异步进程事件发布时必须重新读取当前工作区状态并核对转换，复用单写入者的原子发布；不能把启动时缓存的旧 manifest 覆盖到后来保存的标注或开发审阅上。

首版每个工作区只运行一个分析任务。双击、重复请求或多个页面发起同一操作需要服务端幂等与占用检查。浏览器传递受约束的任务与配置选择；可执行程序和固定参数由本机配置及适配器决定，不能把页面输入直接当作 shell 命令。

状态至少区分：准备运行、运行中、请求停止、已停止、异常中断、运行失败、结果待校验、结果无效、结果已保存。是否能应用继续由提案的当前基线核对决定，而非运行状态决定。状态名称可在实现中调整，含义不可合并成一个“完成”。

事件按真实来源记录。进程/流结束、工具事件、Agent 自述、程序校验结果分开；不将模型内部推理作为产品阅读前提。日志以惰性分页和有上限的纯文本保存，超限原因可见，不让日志淹没功能内容或撑爆工作区。

### 结束、取消和重开

- 正常结束：等待输出写入完成，只读取约定目录下大小受限的普通文件，核对任务身份并重新执行已有检查，再发布待审结果与运行记录。拒绝符号链接或任意返回路径。退出码 0 本身不构成有效结果；receipt 是完整提交标记，不是防篡改凭证。
- 收件中断：完整输出可按原任务重新校验并幂等收回；恢复收件仍遵守已保存的取消决定。半写文件和缺失 receipt 保持不完整，不能标为成功。
- 请求取消：先记录停止请求，收到可靠终止确认后才标“已停止”。以待审提案的落盘发布作为与取消竞态的确定边界：提案先发布则取消返回已完成；停止请求先被接受则晚到输出及重开后的恢复收件均不自动导入，文件保留供核对。
- 关页面：本机服务仍在运行时可重新连接查询；关页面不能被描述为已停止 Agent。
- 工作区正常关闭：先停止并确认其拥有的分析进程及必要子进程结束，再释放工作区锁；关闭失败时保留真实状态。
- 服务异常退出：重开后恢复已保存记录。无法证明原运行已结束时显示“执行状态待核对”，不依据旧 PID 猜测进程身份，也不自动重跑或杀死不明进程。
- 重试：用户明确发起新的尝试。重试前重新核对基线；发生变化时提示按当前版本重新准备任务，保留旧尝试与旧结果。首版不承诺模型会话无缝续跑。
- 代码或标注变化：正常代码更新仍继续；正在运行的任务固定原版本。迟到结果可保存、阅读和拒绝，应用仍被已有冲突检查阻止。

## 6. 第一个适配器：本机 Codex

建议先接用户已经使用的 Codex。官方 [非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode) 提供 `codex exec`、JSONL 事件和已有 CLI 登录复用；可作为有限任务的第一种适配方式。这只是接入依据，尚未证明本项目在用户所装版本及 Windows/Linux 下的兼容性。

实现前先固定受支持的 CLI 版本/能力清单，核对可执行程序发现、事件格式、失败退出、取消和权限配置。以实际已安装版本为准；缺少依赖或权限不符时明确说明并保留手动交接。当前准备环境未发现 `codex` 可执行程序，本轮未安装或试运行模型。

运行目录位于目标源码树之外，使用冻结任务包中的已索引源码、已构建的 RepoGraphia 查询工具和独立输出目录。启动时核对配置，并记录实际执行环境；本机服务凭据不传给 Agent，认证交给现有 Codex，页面不收集密钥。任务目标通过数据/标准输入传递，不拼接可执行 shell 字符串。

必须明确工程边界：Skill 和任务包约束语义/输出范围，**不是宿主权限隔离**；文件只读也不等于无法执行文件。首个适配切片要验证实际写入范围、配置继承、工具/外部连接和终止行为，确认能够满足本项目的分析边界。需要执行目标项目、修改其源码或放宽宿主权限时，应停止该次受限分析并呈现真实原因；不能为跑通自动改成无限权限，也不能在未经验证时承诺绝对隔离。

原 `AGENTS.md` 明确默认不运行 AI。实现 M4 时要同步写明新增的**显式配置、显式点击启动的功能分析模式**及其权限边界，保留默认工作区与离线命令的原有行为。本计划不修改现行运行契约。

## 7. 里程碑

| 小阶段 | 具体交付 | 通过标准 |
| --- | --- | --- |
| M4.1 运行与收件基础 | 单一 Codex 适配器、固定任务到运行尝试的绑定、可靠状态与独立输出、已有校验/导入衔接 | 先用可控替身覆盖失败、重复与竞态；再按已获授权的环境验证真实 CLI 能力。跨平台支持、取消和权限边界没有通过前，不宣称可用 |
| M4.2 工作台使用闭环 | 任务详情启动/取消/重试、重新连接、结果到达提示、按功能读本批变化并进入现有审阅 | 用户从图上发起后可在同一工作台完成待审交接；后台变化保留原阅读与草稿；结果可解释且能定位到精确依据 |
| M4.3 跨平台与真实使用验收 | Windows/Linux、断开与重开、迟到与冲突、旧手动流程和导出兼容 | 完成粗图→功能深入→代码变化后续分析的受限试用；记录实际结果、未探索部分和人工可读性反馈 |

M4.1 是工程验收点，M4.2 接通用户流程，M4.3 后才能宣布 M4 完成。每个通过的阶段提交代码并更新检查点；不得将计划、替身回放或已有 M1～M3 的 CI 当作新 Agent 集成已验证。

## 8. 核心验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 双击启动、多个浏览器页面同时操作 | 服务端仅产生一次有效启动，或明确报告另一运行占用 |
| 已配置运行返回合规提案 | 校验后进入待审，功能图与人工决定在应用前不改变 |
| 进程成功但输出缺失、破损、越范围，或 receipt 的任务身份/摘要不匹配 | 显示结果不完整或无效，保留原因，不产生可应用提案；一致 receipt 也不证明作者或执行过程真实 |
| 收件发布时失败、重开后重新收件 | 原输出保留、重复校验幂等，运行记录与提案身份可以核对 |
| 启动/运行/校验三个时刻请求取消 | 状态准确，已停止前有确认依据，晚到输出遵守取消决定 |
| 运行中保存代码或编辑标注 | 当前图照常更新，原任务固定，旧结果不能应用到新基线 |
| 浏览器断线、服务正常关闭、服务崩溃 | 分别显示重连、已确认结束或状态待核对，不自动重复模型调用 |
| 未安装 CLI、未登录、版本不兼容、需要额外权限 | 原因可读，原手动路线可用，不自动安装、授权或放宽权限 |
| 带特殊字符的路径、异常事件、恶意日志/提案文本 | 参数与内容保持数据身份，不执行 HTML，不越界读取产物 |
| 用户先读名称与一句说明，再展开依据与未确认事项 | 能说清本批新增/修订的内容、主要依据及至少一个未确认部分；可继续读完整条件和源码 |
| 重新打开工作区和导出离线报告 | 已保存任务、运行、提案、决定恢复；离线 HTML 保持原快照、引用核对和无网络属性 |

CI 使用可控的执行替身验证契约与浏览器行为，不默认消耗真实模型。真实 CLI 试跑独立记录版本、环境、输入、实际活动与限制；不把替身回放称为真实 Agent 运行，也不以点击数代替内容理解验收。
