# 开发过程与结果审阅

**「开发审阅」** 把一轮开发的声明目标、功能记录变化、代码差异和人工结论放在同一个左右工作台。先看名称与一句说明，再按需要查看原标注、源码和完整证据。每份比较固定开发起点和审阅终点的代码、标注版本。

## 一轮开发的使用方式

1. 打开持续工作区，等到当前代码核对完成、需要保留的功能标注已保存。
2. 点击 **「开始一轮开发」**。填写标题；可展开补充目标说明、声明来源、明确关注的功能和验收点。每行填写一个验收点。点击建立起点，工具重新分析并核对已保存输入，然后一起固定代码、标注与这些声明。
3. 在现有编辑器或 Agent 中开发并保存代码。工作区继续自动核对、完整重建代码图；正在阅读的版本保持原样。
4. 明确切换到要审阅的新版本，进入 **「开发审阅」**。左边选择目标、功能、未归属项或已保存记录，右边查看该对象的前后内容和待确认事项。
5. 从功能详情下钻到 **「代码变化」**，查看同一对固定版本中的文件和源码差异；也可打开起点、审阅版的功能地图。
6. 对本轮整体、某个功能、变化文件或验收点，分别追加人工审阅、外部验证结果或补充解释。收到成功保存提示后，记录才写入工作区。
7. 后续代码或标注变化时重新比较。旧比较与结论保留在「记录」中，新的比较重新显示尚无审阅。需要留档时点击 **「导出这次审阅」**。

旧任务只包含标题，也能打开本面板。它们显示未单独声明的功能范围与验收点，不从标题猜测计划。建立起点包含当时已经保存的未提交修改，仍不以 Git HEAD 代替实际工作区。

## 怎么读这些变化

| 页面内容 | 它说明什么 |
| --- | --- |
| 功能描述前后对比 | 人或 Agent 编写的名称、一句说明、详细解释、所属层级、待确认问题发生了什么变化 |
| 关联记录变化 | 某个明确的功能与代码关联被新增、修订、移除，或原关联的人工决定发生变化 |
| 原标注涉及的变化文件 | 原记录中的代码或证据文件路径与本轮变化文件相交，是继续检查的线索 |
| 本轮新增待复核 | 起点还能匹配的原引用，在审阅终点不再匹配 |
| 起点已有的待复核项 | 开发开始时就已失效、缺少原依据或需要核对的引用，单独保留 |
| 未归属变化 | 发生变化的文件中，仍不能通过明确有效关联归属的代码实体，或没有可供归属实体的源码范围 |
| 选定范围之外 | 有变化的功能记录没有被明确勾选进本轮目标，需要人判断调整理由 |
| 目标功能未见变化 | 当前比较没有观察到该功能记录的变化，目标是否完成仍需另行判断 |

目标范围只包括开始时勾选的功能。勾选父功能不会自动包含子功能，后来的新子功能也不会悄悄加入目标。共享代码不会自动生成新的功能依赖或目标授权。

功能说明发生修订，不等于运行行为改变；旧路径上的文件发生变化，也不证明当前同名实体就是原来的实体。引用状态保留其原始版本、精确源码与静态关系依据。未匹配引用不会跳转到猜测的当前代码。

未归属列表从完整图和明确引用状态计算，不受代码差异预览的 40 条记录预算影响。列表包含变化文件里尚未归属的实体，**不表示每个列出的实体本身都被修改**。文件级关联不能覆盖文件中的所有函数；被拒绝关联不计作当前归属。候选、未知、类型关系、来源停止原因、预算截断与未索引范围仍保留。

## 三种记录分别保存

| 记录 | 需要填写的内容 | 页面如何呈现 |
| --- | --- | --- |
| 人工代码审阅 | 记录者、已审阅／需要修改／留待审阅、判断理由 | 人对这份固定比较的结论，按对象保留每次追加 |
| 外部验证结果 | 来源类型、来源名称、记录者、报告通过／报告失败／受阻／尚未执行、方法和证据摘录 | 明确标为填写者自述；Agent 自述保持可见 |
| 补充解释 | 来源类型、来源名称、记录者、解释文字 | 与程序提取的代码事实分开显示 |

记录者和来源名称是本地自述身份，没有身份认证。命令、日志和链接按文字保存，本工具不会执行它们、访问外部证据地址或独立认证结果。需要使用你原本的测试、运行和审查方式取得证据，再把方法、结果和限制记到这里。

功能图中原有的「关联已接受」只评价功能与代码的关联。它不会初始化本轮开发审阅，也不会自动填写测试通过。点击「已审阅」同样不会修改功能关联决定、判定目标达成或替你完成运行验证。一个验收点可以同时保留人工判断和外部测试自述。

每条记录只绑定它实际比较过的任务、前后代码和标注版本。同一对象可以追加新的判断，旧记录保留；之后新增记录按顺序显示，用户可以看到结论为什么改变。未填写的部分保持未知。

## 版本变化、草稿与并发

后台更新不会替换打开的比较或未保存表单。保存时重新核对当前代码、标注、输入和审阅记录序号：

- 代码或标注已有新版本，旧表单不能写入新比较。可导出未保存记录，核对新版本后重新填写。
- 另一页已经追加记录，当前页显示冲突并保留草稿。先点击「核对最新审阅记录」，看过新增结论后再保存。
- 正在查看已保存历史时保持只读。历史记录不会覆盖当前标注，也不会自动移入新比较。
- 普通代码版本或开发任务切换会保护未保存的审阅草稿。面板内不同对象的草稿仍绑定各自对象及比较。

审阅草稿留在当前浏览器页面中，尚未落盘；页面关闭或刷新不能保证恢复。可以使用 **「导出未保存记录」** 保存带比较版本的草稿 JSON。导出不会自动提交、接受或跨版本重放草稿。

保存过程先写入并核验固定比较，再以一次 manifest 发布追加记录。写入失败、发布前又有源码变化时，不会显示半条成功记录。重开工作区可恢复已经保存的比较、顺序、原目标和来源。损坏的比较文件、错配对象或不连续历史会报错，工具不会自动修补后冒充原结果。

## 导出与已有工作区兼容

**「导出这次审阅」** 下载 JSON，包含固定比较、目标、功能／代码差异以及这一份比较的已保存记录。它可以用于留档和进一步处理。它不是新的功能标注导入协议，也不会由 Agent 自动应用。分享它可能同时分享源码差异、说明与证据摘录。

顶栏原 **「导出报告」** 继续生成固定代码与功能地图的离线 HTML；两种导出用途不同。需要同时保留可浏览的地图和本轮结论时，可分别导出。

已有 M1/M2 工作区继续使用同一条 `workspace` 命令打开。M3 增加可选目标声明和独立审阅记录，不改变 CodeGraph/FeatureMap schema、分析规则、原 `assess`、显式迁移、Agent 修订协议或旧任务起点。当前随附 Skill 1.4 的功能建设任务照常使用；其本层问题、同层粒度与拆分理由规则服务于功能内容构造，开发审阅记录仍由人通过本面板填写。

## 数据与接口

固定比较的 `reviewVersion` 为 1，`comparisonDigest` 覆盖完整可序列化报告，不包含易变的当前时间。前后标注 digest 与现有工作区标注身份一致。immutable `development-reviews/<storageDigest>.json` 保存报告；manifest 的可选 `developmentReview` 保存报告元数据和追加记录。`storageDigest` 核验实际 JSON 字节，`comparisonDigest` 固定比较内容。

所有接口沿用工作区本机 token、Host/Origin、同源请求和禁止缓存约束：

| 接口 | 作用 |
| --- | --- |
| `POST /api/baseline` | 原标题／标注版本参数不变，新增可选 `intent` 声明 |
| `GET /api/development-review?task=&snapshot=&featureDigest=` | 计算或读取固定比较，返回记录、revision、历史及是否可写 |
| `POST /api/development-review/records` | 携带固定比较摘要和 `expectedRevision`，追加一条独立记录 |
| `GET /api/development-reviews/<comparisonDigest>` | 读取已保存比较和记录，历史视图只读 |
| `GET /api/development-reviews/<comparisonDigest>/export` | 导出同一份比较及记录 JSON |

目标说明最多 2,000 字符，明确功能范围最多 1,000 项，验收点最多 50 项；每条记录最多 32 KiB UTF-8，固定报告最多 192 MiB。工作区最多保留 10,000 份开发比较、100,000 条追加记录；超出时明确拒绝新增，不静默截断保存。界面列表分页、预览预算和完整导出彼此独立。
