# M4：功能树的构造与阅读

实施进展（2026-10-23）：M4.1 同数据几何与交互比较已完成，见 [CP47](checkpoints/CP47-function-tree-prototype.md) 和 [布局复用记录](archify-tree-reuse.md)。正式树导航、Skill 1.4 与提案分组的当前行为见 [功能地图](feature-map-visual.md) 和最新检查点；以下保留本方案确定时的范围与验收条件。

2026-10-23。用户明确希望借鉴 Archify 的布局、功能树展开与内容组织，完善 RepoGraphia 的阅读和构造，同时保留底层代码图以及开发审阅。**本文是下一阶段的实施方案，尚未接入新的布局或交互。** 原工作台启动 Agent 的方案保留在 [执行适配提案](analysis-execution-plan.md)，安排在本阶段之后。

## 1. 目标与分工

让人先看懂项目有哪些能力，再沿着已有功能树逐步理解组成，最后按需要打开源码依据和开发变化。构造质量与阅读质量分别验收：一份层级不清的内容不能靠布局修复，一份正确的标注也不能自动保证容易阅读。

| 层 | 继续负责什么 | 本阶段怎样使用 |
| --- | --- | --- |
| 程序代码图 | 所选分析范围内的实体、关系、位置、输入版本、候选与未知 | 提供可查询的事实基础，继续跟随已保存源码重建；不从布局反向生成关系 |
| 功能内容 | Agent 根据固定事实提出名称、说明、显式父子关系与代码关联 | 改善粒度、分解理由、条件和未知的组织；沿用有界任务与人工应用 |
| 阅读投影 | 将同一份功能内容排成图，处理选择、展开、聚焦和定位 | 优先复用成熟布局，独立保存阅读状态；浏览不改写内容与决定 |
| 审阅与历史 | 对应版本上的功能关联决定、开发比较、核验记录 | 从选中的功能进入已有审阅；保持人工决定与代码引用状态各自独立 |

程序能核对引用与结构，不能因此证明功能解释正确。`parentId` 表示功能包含；角色分组、共享代码和候选调用不能变成功能执行顺序。代码实体 ID 仍属于代码快照，功能 ID 的沿用也不构成跨版本代码身份保证。

## 2. 阅读方式

以左侧主画布、右侧阅读区为默认。主画布展示名称与一句解释，右侧承载完整条件、关联代码、依据和审阅。保留暗色工作台与项目地图之间的导航连续性；首先改进功能树，项目代码图复用适用的阅读规则，不在本阶段重写代码图提取。

| 操作 | 预期行为 | 与已有能力的关系 |
| --- | --- | --- |
| 选择节点 | 在右侧读解释，保留画布所在范围 | 已有，继续保留 |
| 展开／收起分支 | 在同一画布向右展示已有子功能，保留祖先和相关同级上下文 | 新增；与当前逐层进入不同 |
| 聚焦此功能 | 复杂分支可单独进入；路径栏保留祖先，返回恢复原选择、展开集合与视口 | 沿用已有进入／返回，补齐与原地展开的衔接 |
| 搜索定位 | 找到隐藏节点时展开必要祖先，再定位并选择；保留返回搜索前视图的路径 | 改进已有搜索，不要求用户逐个猜测分支 |
| 查看关联代码／依据 | 进入本功能的显式映射与原始证据，返回时恢复功能阅读状态 | 复用已有投影、源码定位和引用核对 |
| 继续分析此功能 | 准备现有 M2 固定任务，由用户使用外部 Agent 补充内容 | 与展开已有子功能分开；点击展开不启动模型 |

展开不设置一次或固定层数限制，以已有显式层级和文档预算为边界。初始范围需要控制阅读密度，但所有实际子功能都可到达；隐藏数量和展开入口明确。无子功能只表示当前没有这些标注，不能显示为“已完全分析”。`exploredFiles` 是带文件摘要的 Agent 声明，不能直接转换为每个功能的完成率。

### 空间、文字与动效

- 同一份内容内，展开／收起优先保持已显示节点位置。先评估 Archify 的完整树布局加可见性切换；如果较大树产生明显空白或资源问题，再以同一数据测量局部布局方案。跨内容版本不承诺全部坐标不变。
- 节点按中文名称和一句解释测量尺寸；当前层先保证阅读尺寸，深分支允许画布平移或聚焦。默认视图不为装下全树而把正文缩成小标签。主名称、说明和辅助状态的字号标准在真实视口原型中确定，不照搬 Archify 的极小投影文字下限。
- 画布外框保持左右布局；右侧阅读区可收起、调整占用，窄屏沿用抽屉方式。缩放不使右侧长文一起缩小。
- 展开、收起、聚焦、返回和搜索定位具有可跟随的有限动效；同一时刻优先服务当前操作，快速操作取消旧过渡。保留静止／减少动效路径，不在包含线上播放暗示执行的信号流。
- 候选、失效、待复核和人工决定使用明确文字或图标；同一种颜色不同时承担“功能分类”与“已经通过”的含义。完整限制仍可直接打开。

阅读状态与内容分开：版本身份、聚焦功能、选择、已展开分支、视口和右侧阅读位置属于阅读上下文。后台新代码图或提案不能替换当前上下文；用户切换版本时再核对可恢复对象，已移除或已改变的对象明确提示。本阶段先在现有会话内恢复阅读状态；完整画布状态的跨会话持久化如有需要再单列，不将工作区数据可重开等同于所有视口已保存。

原地展开需要同步修改 `feature-workbench-view.js` 的可见节点投影，以及 `feature-map-view.js` 的 `normalizeView`／`showFeature` 选择规则；当前规则只允许选中当前层的直接子功能。仅增加绘制而继续沿用旧的自动跳层，会破坏展开后的阅读连续性。

## 3. 功能树怎样构造

复用当前 [功能建设与修订](feature-tasks.md) 和 [功能探索 Skill](../skills/repographia-function-map/SKILL.md)。本阶段的改进重点是让内容组织过程更明确，并将其结果与图面阅读一起验收。

1. **先写清本层要回答的问题。** 总览解释主要能力；深入某功能时解释它的组成、条件与边界。查询和修订范围仍以冻结任务为准。
2. **先形成粗图，再按需要分解。** 同层节点尽量具有相近的解释粒度。每个子功能应解释父功能中一个有用、可独立说明的部分；拆分理由要具体，不能仅因文件多、函数多或页面需要更多节点而拆分。
3. **名称和一句说明先让人读懂。** 避免用代码符号代替功能名称；摘要不能去掉改变适用性的关键条件。完整触发、结果和限制保留在说明中，证据留在对应关联和支持／限制检查中。
4. **复用已有功能身份与结构。** 对现有节点增加依据或修订时沿用其身份；改父节点、改含义和改关联均进入显式提案，保留前后差异。结构修改遵守任务的允许范围，局部深入不能擅自调整其他分支。
5. **保留每个功能自己的依据和未知。** 父节点不能借子节点的接受状态或证据自动成立。缺少依据的部分记入问题／未探索事项，不创建空能力来凑齐对称树。未索引区域与未探索区域分别展示。
6. **按功能阅读本批提案。** 把现有摘要、变化理由、支持与限制检查放在对应功能旁，允许查看完整前后内容；整批应用、逐条映射决定和开发审阅仍按原契约保存。

支持／限制 `checks` 当前属于提案批次，并非所有功能都拥有的常驻字段。首版在本批提案内按 `featureId` 展示；当前功能页继续使用实际存在的说明、问题、映射理由与依据。若以后展示历史检查，需同时核对原提案、是否已应用、功能含义版本与原 basis，不能把待审、已拒绝或旧含义的检查当作当前证明。批次 `unexplored` 没有逐项功能归属，不能自动挂成分支节点；完整 claim table 和自评也不能被假定为协议已返回的字段。

其中“实际深度、名称与摘要、支持／限制、显式层级、任务范围”当前已存在，不能重新宣称为新增能力。需要补强的是本层问题、同层粒度、分解理由与图面阅读的配合。实施到构造切片时再更新 Skill 版本与对应参考文档；本次没有修改已安装 Skill 或提案协议。

布局不得为改善外观自动重排功能归属、合并含义或删除限制。旧的平面功能图仍按平面内容展示；生成更深层级属于内容修订，不属于重新渲染。

## 4. 优先复用什么

外部参照固定为 Archify `25cf37080fc8b1dbe758a4efc3935b55f3327083`。已阅读设计／作者规范、Tree 与阅读器实现并查看公开示例；**尚未用同一份 RepoGraphia 数据运行交互对照或验证可嵌入性。**

| 对象 | 优先策略 | 进入正式实现的条件 |
| --- | --- | --- |
| Tree 布局与文字测量 | 先用固定版本生成器做同数据只读对照，再评估复用布局模块 | 中文、多根、宽树、深树与不平衡树可读，依赖范围和接口清楚 |
| 分支可见性、搜索揭示祖先 | 学习并适配展开状态和定位机制 | 可衔接当前选择／聚焦／返回；键盘、快速操作和隐藏选中项行为明确 |
| 阅读器与动效 | 复用适合的实现或小模块，保持单一阅读中心 | 满足现有离线 CSP、暗色左右布局和阅读状态；不引入重复界面体系 |
| 作者规范与 Skill 方法 | 纳入问题驱动的内容组织、分解与自评 | 保持 RepoGraphia 的固定任务、精确引用、支持／限制和人工决定契约 |

对照原型的适配只投影 `id/title/summary/parentId` 等已存在内容。Archify Tree 要求单根，RepoGraphia 允许多根：可以使用显式的“项目功能”导航根，但它不是有证据或可审阅决定的新功能。两边 ID 字符规则也不同，适配器需要无碰撞的一一对应表及原 ID 反查，不能通过删除字符产生混淆。原始功能内容、依据、审阅记录另由 RepoGraphia 持有。

Archify 的主要交付接口是输入描述文件后生成独立 HTML，并非已经验证过的可嵌入组件。先证明阅读收益，再决定提取布局模块还是适配其阅读层；不预先承诺整套集成。引用原代码时保留所需许可和来源，固定版本，不在运行时远程下载。未提交源码的内容快照继续使用 RepoGraphia 自身依据，不能伪装成 Archify 的 Git commit 证据。

选型失败必须有具体依据，例如无法保持中文阅读尺寸、无法独立于全局阅读器接入、破坏离线约束或状态衔接成本明显高于局部复用。记录同数据结果后再缩小复用范围，避免仅因接口不同就重新实现全部布局。

## 6. 验收与停止条件

阅读验收分别记录：人能否从总览指出主要能力；是否理解当前功能与父／子功能的关系；展开、聚焦和返回后能否找回位置；能否找到具体依据并识别未确认内容。初轮可记录操作与反馈，不把少量试用称为普遍可用性结论。

工程检查围绕实际新增风险：

- 结构：多根、不同深度、不平衡分支、较多同级、长中文、空关联、无子功能；完整内容始终可访问，原地展开不伪造结构。
- 导航：搜索隐藏节点、收起包含当前选择的分支、聚焦后返回、源码往返、尺寸改变、快速连续操作、键盘和减少动效。
- 几何与阅读：文字溢出、节点重叠、连线穿节点、默认字级和右栏占用；浏览器测量、截图与实际视觉审阅分开记录。
- 版本与决定：读取旧版本时后台更新、迟到提案、依据待复核、未保存编辑、重开与离线导出；原依据和人工历史始终保留。
- 兼容：按修改面运行现有层级／场景／工作台与 CSP 回归，实际实现遵守仓库 Windows/Linux 门禁。文档阶段不重复执行运行时测试。

真实样例不提交公共仓库；若当前环境缺少原配对数据，先交付公开／手写夹具的结构结果，将真实阅读验收明确留待本地完成。不得用夹具宣称真实用户样例已通过，也不得为了展示深树改写原样例。阅读和构造切片通过前，不用接入自动运行器替代这部分验收。
