# 持续工作区使用说明（M1）

持续工作区让项目地图跟随已保存代码，并保留开发起点、标注和历史版本。它沿用原有暗色地图工作台，在外层增加版本选择、保存状态和“本轮变化”。功能语义的局部续分析与修订属于 M2，本版仍使用现有功能标注和显式迁移规则。

## 启动与重开

在已经安装并构建的 RepoGraphia 目录运行：

```sh
node dist/cli.js workspace "../my-app" --out "../repographia-workspaces/my-app"
```

打开终端输出的完整网址，例如 `http://127.0.0.1:端口/#token=凭据`。服务只绑定本机 `127.0.0.1`，默认自动选择空闲端口；网址末尾的凭据用于本次连接。终端保持运行，按 `Ctrl+C` 关闭。服务不会自动打开浏览器。

以后执行同一条命令，使用本次输出的新网址即可恢复。重开会先恢复保存的版本选择，再核对当前文件；恢复旧图不等于已经完成本次核对。旧端口和凭据不保证继续有效。

| 参数 | 用途 |
| --- | --- |
| `<repository>` | 被分析的项目目录 |
| `--out <directory>` | 新的或已有的 RepoGraphia 工作区目录，必须在被分析项目之外 |
| `--project <tsconfig>` | 相对项目根目录选择一个配置，例如 `packages/app/tsconfig.json`；重开时保持相同选择 |
| `--features <features.json>` | 仅首次建立工作区时载入标注，必须匹配首次成功分析的代码图 |
| `--port <number>` | 固定本机端口；默认 `0` 表示自动选择 |

例如选择 Monorepo 中的一个项目：

```sh
node dist/cli.js workspace "../my-monorepo" --project "packages/app/tsconfig.json" --out "../repographia-workspaces/app" --port 4173
```

工作区绑定项目的实际绝对路径和配置选择。一个配置仍只代表一个选定的编译项目，不代表覆盖整个 Monorepo。改变项目根目录或改用另一个配置时，建立独立工作区。

新工作区可使用尚不存在的目录或空目录；已有工作区可以恢复。普通离线报告目录不能直接当作工作区目录。与 `analyze --out` 每次必须使用新目录的规则不同，`workspace --out` 正是用于重复打开同一份保存数据。

## 一轮开发怎么用

1. 打开工作区，查看顶部核对状态。探索地图，应用需要保留的功能标注，等到“标注已保存”。
2. 点击 **「开始一轮开发」**，填写本轮目标，再点 **「建立起点」**。工具重新分析并核对当前已保存文件，固定代码图和当时的标注版本。
3. 在你原本使用的编辑器或 Coding Agent 中继续编码，保存文件。工作区会核对变化并生成新代码版本。
4. 完成当前编辑后，点击 **「查看新代码版本」**，进入 **「本轮变化」**。比较的是选定任务起点与“正在审阅”的代码版本；可以从任务列表切换历史开发任务。
5. 查看文件变化、源码差异、声明和关系依据，以及编译诊断、范围和限制。需要回看开发前的内容时，点击 **「查看起点地图」**；需要固定交付记录时，点击 **「导出报告」**。

起点包含建立时已经保存的未提交修改。因此，之前已存在的改动不会被算成本轮新改动。工具不会用 Git HEAD 替代实际工作区起点，也不会因为点击“开始一轮开发”而启动 Agent、目标应用、构建或测试。任务标题是你填写的目标，代码差异不能证明修改者、Agent 执行进度或功能完成。

## 三类版本分别表示什么

| 版本 | 含义 | 何时改变 |
| --- | --- | --- |
| 当前代码版本 | 最近成功分析并核对过输入的图，带有核对时间和范围 | 输入变化后的完整重建成功发布 |
| 本轮任务起点 | 开始该任务时实际已保存的代码图和标注版本 | 每次建立新任务产生新记录，原起点保留 |
| 正在审阅的版本 | 当前页面实际展示的代码图及标注版本 | 你主动切换版本或载入更新后的标注 |

后台发布新图时，正在审阅的内容继续停留在原版本，界面提示有新版本可看。功能标注仍依据旧图时，会显示其依据版本和待复核状态；原文字、证据、人工决定及历史保留。接受一个版本的映射不会自动表示后来的代码也经过审阅。

任务起点地图及旧标注版本只读。它们保留当时的功能内容和决定，不能原地覆盖。返回当前版本后才继续编辑当前标注。工作区保存代码版本、任务选择和标注版本；画布缩放、局部展开等页面状态仍以当前页面的状态管理为准。

## 保存、冲突与导出

持续工作区中的接受、拒绝、导入、迁移和已应用修正，会提交为新的标注版本。顶部显示“正在保存标注…”时写入尚未完成，显示“标注已保存”才表示本地工作区已保存。编辑框里尚未点击应用的内容仍是表单草稿；关闭或刷新页面不会恢复这些未应用文字。

多个页面可以浏览同一个工作区。保存会检查页面开始编辑时依据的标注版本；若另一页已更新，当前页显示 **「保存冲突 · 草稿已保留」**，不会覆盖另一页的新记录。可先 **「导出草稿」**，核对后选择重试或 **「重载已保存内容」**。重载会放弃当前未保存内容；尚未应用的表单文字应先复制保留。

连接中断或保存失败时，页面会保留当前已应用草稿并显示实际状态。切换版本和建立起点前，需要先应用或取消表单编辑，并完成保存。页面内的草稿保留不等于已经落盘，关页前应处理保存状态。

**「导出报告」** 下载当前固定代码和标注版本的独立 HTML，可直接离线打开。导出的 HTML 没有持续工作区连接，之后在其中编辑仍需“导出标注 JSON”保存。功能映射页的 JSON 导出也可用于备份和原有 CLI 流程。

## 首次标注与旧报告

首次创建时，可以带入已经与首次代码图匹配的标注：

```sh
node dist/cli.js workspace "../my-app" --out "../repographia-workspaces/my-app" --features "./reports/my-app-features/features.json"
```

首次图来自当前实际源码、配置和依赖，初始标注必须与该图匹配。重开已有工作区时省略 `--features`；之后通过页面导入与工作区保存版本配对的标注。功能提案仍沿用 [README 中的外部 Agent 和固定图流程](../README.md#4-让-agent-使用-skill-生成功能提案)，本版没有自动派发任务或合并迟到提案的功能。

本版分析输入身份引入 `inputRevision: 1`，把配置继承、已读内容、目录和解析查询等纳入快照计算。因此，即使源码没改，旧版图和新分析图的快照 ID 也会不同。旧 `graph.json` 和与之配对的 `features.json` 仍可照常阅读或重新渲染，不会自动重写，也不需要为了继续浏览而重新运行 Agent。旧版 `features.json` 不能仅因源码未改就直接作为新工作区的 `--features` 输入。需要换到新图时，保留旧配对数据，先按 [显式迁移流程](feature-migration.md) 准备新版本，再导入匹配的标注；不要手改快照 ID。

工作区的快照文件在 `graph` 外还有输入记录，不能直接当作标准 `graph.json` 传给 Agent CLI。原有离线 `analyze` 可以为相同项目路径、配置及相同输入生成标准图文件；以实际快照 ID 核对配对关系。每批 Agent 分析固定同一份图和标注，不混用更新中的版本。

## 更新范围和差异的含义

本版只观察磁盘上**已经保存**的输入。选定 `tsconfig` 决定 TS/JS 索引范围；没有根配置时使用已有 TS/JS 扫描规则。编辑器内未保存内容不会进入图，未支持语言、未索引区域和缺少类型依赖仍在分析边界中显示。

文件监听提供更新线索，默认使用约 **300 ms 的事件合并窗口**，并每 **10 秒核对一次输入**。监听不可用时，周期核对仍会继续；也可点击“检查更新”。这些间隔是调度设置，实际图更新时间还取决于项目规模和分析耗时。

每次需要更新时，在 Worker 中完整建立 TypeScript Program 并重建代码图。分析读取的源码、根配置、继承配置、类型声明和模块解析环境会记录；发布前再次核对。若分析期间输入继续变化，暂不发布该结果，保留上一份有效图，等下一次事件或周期核对重试。配置错误等失败也保留原图并显示原因。核对描述当时已检查的输入，文件系统本身并不是原子快照。

“本轮变化”区分以下情况：

| 显示 | 可以据此理解的变化 |
| --- | --- |
| 进入索引 | 文件现在属于分析图；可能是新增源码，也可能是配置或范围改变 |
| 离开索引 | 文件不再属于分析图；不能仅凭这一项判断磁盘文件已删除 |
| 源码变化 | 两份固定图中的该文件内容不同 |
| 分析变化 | 源码未改，但声明或关系记录改变，可能涉及其他文件或解析环境 |

实体和关系 ID 只在各自快照内有效。比较使用源码和结构依据，不把 ID 改变或同名当作语义对应证明。界面还保留诊断、分析契约、覆盖范围、候选、未知、值来源停止原因及预算截断信息。源码差异和长列表有展示预算，显示的变化窗口也不保证是最小编辑序列；完整依据保存在原代码版本中。

本版实现自动核对和完整重建，未实现真正局部增量提取，也未实现功能含义的局部增量修订。代码图有更新时，功能图仍遵守原来的整份快照失效与显式迁移规则。功能关联的接受状态、代码审阅结论、测试验证是不同的事情。

## 数据保存与恢复

| 工作区文件 | 内容 |
| --- | --- |
| `workspace.json` | 项目绑定、当前版本指针、任务起点和正在审阅的版本 |
| `snapshots/<id>.json` | 固定代码图及其输入核对记录；包含完整的已索引源码 |
| `features/<digest>.json` | 固定的完整标注文档版本 |
| `workspace.lock` | 当前占用该工作区的服务进程记录 |
| `workspace-acquire.lock` | 打开或恢复工作区时使用的短期独占锁 |

新版本文件写入后才发布清单指针，旧版本保留。清单记录每个快照文件的 `storageDigest`，读取和复用时检查实际内容，损坏的文件不会被当作有效新图。一个工作区同时只允许一个服务进程持有写入锁；多个浏览器页面共享该服务，并通过标注版本检查处理冲突。

正常退出会释放进程锁，下次启动可恢复。若进程恰好在获取工作区期间退出，可能留下 `workspace-acquire.lock`；遇到相应提示时，先确认其中记录的进程已经停止，再清理这个短期锁并重试。损坏或不完整的数据应保留现场检查，不通过改哈希强行打开。

本机服务没有远程遥测，也不执行目标代码或 AI。工作区和带源码的导出报告包含项目源码及本机路径信息，按项目资料保存和分享即可。完整实现与输入身份契约见 [架构说明](architecture.md)。
